# レイアウト関数（DOM 非依存）

`WemaBoard` のレイアウト系メソッドは、次の純粋関数の結果を `updateNote` で反映するだけの薄いラッパー。
関数は `src/layout.ts` にあり、`src/index.ts` から export している（サーバー側で使うため DOM に触れないこと）。

```typescript
computeAlignment(notes: LayoutNote[], alignment: NoteAlignment): NotePosition[];
computeDistribution(notes: LayoutNote[], direction: DistributeDirection): NotePosition[];
computeAutoLayout(notes: LayoutNote[], edges: LayoutEdge[], options?: { noteIds?: NoteId[] }): NotePosition[];
```

## `computeAutoLayout` の配置の決め方

- 今の配置を出発点にする。結果の左上は、対象の付箋が今占めている範囲の左上に合わせる（固定の座標へ移動しない。一部の付箋だけを整列したときに、対象外の付箋の上へ飛ぶため）。順序の決め手がないときは、今の位置の左から順（同じなら上から順）にする
- 段は「根からの最長距離」で決める。最短距離にすると、近道の線（A→B、A→C、B→C の A→C）で B と C が同じ段に並び、線が真横に走る。循環は、深さ優先探索で訪問中の付箋へ戻る線を外して解く
- 1 つの段に並ぶ単位（`Unit`）は 3 種類: 付箋 1 枚、折り返した兄弟のかたまり、段を飛び越える線の通り道（`passing`、大きさ 0）
- 横の位置は、段ごとに「親の中央」（下りの掃引）と「子の中央」（上りの掃引）へ寄せることを繰り返して決める。寄せる先で並べ替えるので、線の交差も減る。最後を上りの掃引にして、親が子の中央の上に来るようにしている
- 段を飛び越える線は、付箋から付箋へ 1 本の線として描かれる（途中で折れない）。そのため両端の付箋は通り道だけに合わせ、通り道は付箋より優先して場所を取る（`PASSING_WEIGHT`）。どちらかをやめると、線が途中の段の付箋の裏を通る
  - 制限: 1 枚の付箋が段を飛び越える線を 2 本以上持つと、その付箋は通り道の平均の位置に来るので、線が通り道から外れて途中の付箋の裏を通ることがある
  - 制限: 通り道は「線の本数 × 飛び越える段数」だけ作る。深い鎖に長い近道の線が大量にある入力では遅くなる（1000 枚の鎖の先頭から全付箋へ線を引いた例で数秒）
- 重ならないことは `spread()` が保証する（順序と間隔を保ったまま、望む位置との差の二乗和を最小にする）。段の中の位置を別の方法で動かさないこと
- 子を持たない兄弟の折り返しは 16 枚以上から（`WRAP_MIN`）。折り返すと、2 行目以降への線が上の行の付箋の裏を斜めに通り、付箋のあいだに線の断片が見えて読みにくい。1 行で並べたほうが線は読めるので、1 行では広すぎる枚数になるまで折り返さない
- 段と段の間隔は `gapBelow()` が決める。そのあいだの線の横の広がりに比例させ、`V_GAP`（60px）から `MAX_V_GAP`（150px）の範囲に収める。接続線の曲線（`computeEdgePath`）は、両端で「長さの 0.4 倍、最大 150px」だけ縦に進む。間隔がそれより狭いと曲線が折り返して波打ち、同じ親から出る線どうしが交差する。`FAN_SLOPE` と `MAX_V_GAP` はこの描き方から決めた値なので、`computeEdgePath` の係数を変えたら合わせて直すこと
- 段の間隔（`V_GAP`）を `AUTO_ANCHOR_ROOM`（`src/utils/geometry.ts`）より小さくしないこと。小さくすると、横に離れた子への線が左右の辺から出て、隣の付箋の裏を通る
- 接続線のない付箋は、つながったまとまりの下に格子で置く
